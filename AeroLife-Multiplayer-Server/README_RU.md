# AeroLife 0.7 — сервер комнат

Это настоящий WebSocket-сервер для Windows-клиента AeroLife 0.7. Публичный постоянно работающий экземпляр в поставку не включён. Один экземпляр сервиса обслуживает список комнат, а не только одну комнату.

## Бесплатное размещение на Render
1. Зарегистрируйтесь: https://dashboard.render.com/register . Пароль никому не передавайте.
2. Создайте собственный Git-репозиторий и загрузите **содержимое этой папки в корень**: Dockerfile, server.mjs, kinds.json, package.json, package-lock.json, render.yaml. Подключите этот репозиторий к Render.
3. New → Web Service → ваш репозиторий. Runtime: Docker; Instance Type: **Free**. Health Check Path: `/health`. Либо создайте Blueprint из включённого render.yaml. При отсутствии Free не выбирайте платный тариф автоматически.
4. После успешного Deploy скопируйте HTTPS-адрес сервиса, например `https://aerolife-имя.onrender.com`. Открытие `/health` должно вернуть JSON с `ok:true`.
5. В игре F9 → поле адреса: `wss://aerolife-имя.onrender.com` (без `/health`) → имя → Подключиться. Другу нужен **тот же адрес**. Затем владелец создаёт комнату с названием и необязательным паролем; друг обновляет список и входит, указав пароль в том же поле.

По документации Render, проверенной 22.10.2026, Free: 750 instance-hours на workspace в месяц, сон после 15 минут без входящих HTTP/WebSocket-сообщений, холодный запуск может занимать около минуты. WebSocket-сообщения считаются активностью. Лимиты, региональная доступность, проверка регистрации и условия могут измениться. Никто не гарантирует вечный бесплатный сервер. Нет дисковой БД: перезапуск теряет комнаты. Не отключайте сон искусственными постоянными запросами.
Источники: https://render.com/docs/free и https://render.com/docs/websocket .

## На своём Windows-компьютере / LAN
Установите Node.js 22 LTS: https://nodejs.org/en/download . Распакуйте сервер и запустите START_SERVER.cmd. Первый запуск скачивает зависимость ws через npm; это требует интернета. На том же ПК используйте `ws://127.0.0.1:8787`; на другом ПК в домашней сети — `ws://ЛОКАЛЬНЫЙ_IP_СЕРВЕРА:8787`. Владелец должен разрешить нужный входящий TCP-порт в брандмауэре для доверенной сети. Не выключайте брандмауэр целиком. localhost на компьютере друга НЕ означает ваш компьютер.
Для интернета предпочтителен Render/WSS. Простое включение LAN-сервера не создаёт публичного адреса и не обходит NAT. Незашифрованный ws вне доверенной LAN не рекомендуется.

## Права / ограничения версии
- До 8 комнат, до 8 игроков в комнате, до 120 предметов. Единственная карта `aero_world`, режим `sandbox`. Выбора других карт и режимов пока нет.
- Владелец: роли, кик, бан, строительство. Администратор: правка и модерация более низких ролей. Редактор: все предметы. Строитель: собственные. Посетитель: движение, чат и использование механизмов.
- Права проверяются сервером. Пароли хешируются scrypt, не рассылаются клиентам. В клиентских настройках пароль комнаты не сохраняется. Для приватности используйте WSS.
- Это гостевые идентификаторы, не аккаунты: бан блокирует текущий гостевой билет. Сброс билета позволяет обойти бан; это не полноценная система античита/аутентификации.
- Общие предметы, их настройки, удаление, управляющие кнопки, выходы логики и физические положения синхронизируются. Владелец рассчитывает логику и физику. Движение игроков и машин владельца/гостей показывается другим, но общей физики автомобиля, пересадки в чужую машину и сетевых столкновений машин нет. Движение машин остаётся локальным, кузов у другого игрока — визуальная копия. NPC и городской транспорт не имеют серверной симуляции.
- Открытое меню владельца приостанавливает его симуляцию мира. Передача владения при выходе отсутствует: уход владельца закрывает комнату.
- Сетевая сцена сессионная: выход из комнаты восстанавливает личную локальную сцену. Новые сетевые постройки отдельно не сохраняются. При создании комнаты начальные предметы берутся из локальной песочницы владельца. Личный прогресс не перезаписывается сетевой сценой.
- Остановка сервиса/сбой соединения требует повторного входа; автоматического восстановления комнаты нет. Это первая рабочая сетевая версия, не production-сервис.

## Проверки разработчика
`npm ci --ignore-scripts` → `npm test`. Проверяются пароль, список комнат без утечки пароля, роли/собственность, предметы/настройки, чат, координаты, кик/бан и выход владельца. Реальная пара Godot-клиентов дополнительно проверялась локально. Публичный Render/WSS после регистрации нужно проверить отдельно.
